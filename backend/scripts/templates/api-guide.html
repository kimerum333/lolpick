02. 인증과 중복 요청

Google 로그인 흐름

  1. Supabase Google OAuth를 완료하고 access token을 얻습니다.
  2. 새 로그인 후 5분 이내 POST /auth/session 호출. Bearer + UUID Idempotency-Key, 본문 없음.
  3. 응답의 sessionExpiresAt을 보관하고 선택 시즌을 명시합니다.
  4. SDK의 TOKEN_REFRESHED에서는 현재 토큰만 갱신합니다. session 등록을 새 로그인처럼 반복하지 않습니다.
  5. 6시간 만료·서버 철회 시 개인 화면을 비우고 새 Google 로그인을 안내합니다. 같은 세션 UUID는 재활성화되지 않습니다.

쓰기와 재시도

  • 필수 Idempotency-Key: session, cheer, bets의 POST 세 가지.
  • 사용자가 새로운 작업을 제출할 때 crypto.randomUUID()를 생성합니다.
  • 응답을 못 받았을 때는 동일 입력·동일 키로 재확인합니다. 키만 바꾸면 이미 커밋된 작업과 구별할 수 없습니다.
  • 공급자 갱신, 활성화, 종료, 결과 처리에는 현재 UUID 헤더가 필수가 아닙니다. 서버의 상태·원장 검증이 반복 효과를 차단합니다.
  • 429/503은 Retry-After를 확인합니다. 금융 POST에 무조건 자동 재시도를 걸지 않습니다.

공개 API는 Authorization 없이 요청합니다. Bearer를 보낸 공개 요청은 유효한 Google·서버 세션도 검사하므로 만료 토큰을 공통 헤더에 붙이면 공개 화면까지 실패할 수 있습니다. 개인·관리자 API는 Authorization: Bearer <ACCESS_TOKEN>을 사용합니다.

인증 확인은 서버가 검증한 Google identity와 DB 회원 type을 기준으로 합니다. user_metadata·프론트 역할 값으로 관리자 권한을 결정하지 않습니다. 운영 관리자 작업은 MFA aal2가 필요합니다. DB 연결정보·PandaScore 토큰·서비스 역할 키는 프론트 코드에 넣지 않습니다.

03. 공통 응답 규칙

계약프론트 처리
API 접두사/api/v1. 아래 경로는 이 접두사 기준. 이벤트 ID는 현재 시즌 public_code와 동일.
외부 식별자season/event/match는 공개 문자열 코드, team은 공급자 외부 문자열 ID. DB BIGINT와 섞지 않음. team ID는 공급자별 유일하며 반드시 해당 경기/시즌의 응답에서 선택.
시간Season/Match/Event의 startsAt·endsAt·apiSyncedAt은 UTC epoch 밀리초 또는 null. 세션/배팅/응원 시각은 타임존 포함 ISO 8601. 표시에는 Intl.DateTimeFormat('ko-KR',{timeZone:'Asia/Seoul',...}) 사용.
미정 값teams/teamDetails 두 슬롯의 null은 TBD. startsAt=null은 일정 미정. 기간 null을 1970년으로 바꾸지 않음. score=null은 미확정, winner=null은 무승부·취소·미확정 상황을 result와 함께 판정.
풀·순위pools[0]/[1]은 팀 A/B의 실제 차감 원장 합계, 환불 제외. 0 합계 시 비율은 0. TOP 5는 금액 내림차순, 동액이면 생성 시각·거래 순서. myRank는 본인이 선택한 팀의 순서.
배팅·정산 상태Match status는 scheduled/live/finished/settled/cancelled. settlementStatus는 pending/settled/refunded. Bet status는 pending/won/lost/refunded. won의 payout은 원금을 포함한 총 반환액, lost는 0, pending은 null.
무보상 포인트무료 가상 포인트. 시즌별 잔액 분리. 실제 돈·이체·환전·외부 경품 없음. initialPoints는 시즌 설정이며 회원의 전 시즌 합산 잔액이 아님.
인장시즌 응원 팀이 출전한 경기에서 반대 팀 선택은 betrayal. 인장 철회는 이후 응원·환불로 복구되지 않음. 응원 팀이 없는 경기는 cheerAction=null. 종료 시 계약이 finalizedAt으로 닫힘.
배팅 성공200 응답을 받은 뒤 상태 반영. POST /auth/bets의 currentPoints/cheer는 응답 시점 스냅샷. GET 이력의 두 필드는 null이므로 잔액을 0으로 덮어쓰지 않음.
신선도·장애PandaScore 최대 신선도 기본 4500초. 오래된 데이터는 배팅 차단. 보유한 공개 장애 스냅샷은 X-Data-Stale:1, X-Data-Age-Seconds로 구별하고 배팅을 닫음. 최초 조회·재시작 후 보존 보장은 없음.
캐시·계정 전환개인·관리자·인증/쿠키 포함 응답은 no-store. 로그아웃/계정 전환 시 Vue의 개인 잔액·계약·이력·내 순위를 제거. 응답이 뒤늦게 도착해 이전 계정을 다시 표시하지 않도록 요청 세대 또는 취소 처리.
입력본문 32KiB 한도, JSON 객체만 허용, 중복 JSON 키/쿼리·알 수 없는 필드 거절. amount는 1..9007199254740991의 정수이며 bool/문자열/소수는 거절. 실제 잔액 초과는 409.

05. 오류와 배팅 차단

{ "detail": { "code": "betting_closed", "message": "Betting is closed for this match." } }

detail.code로 화면을 분기합니다. X-Request-ID는 문의·오류 추적용입니다. 서버 메시지를 HTML로 삽입하지 말고 텍스트로 표시합니다. 네트워크 실패는 커밋 여부가 확인되지 않은 상태이며 배팅 실패로 단정하지 않습니다.

HTTP의미 / 주요 코드화면 동작
400 / 401인증 형식·invalid_token·session_missing·session_expired·session_revoked·upstream_session_missing개인 상태 제거. 토큰 자체 만료와 서버 세션 만료를 구별. 서버 세션 만료·철회는 새 로그인.
403admin_required / admin_mfa_required관리자 또는 MFA 권한 부족. 일반 사용자 화면에서 관리자 API 호출 금지.
404match_not_found / season_not_found / member_not_registered없는 리소스 안내. 목록은 필터가 매칭되지 않으면 빈 items/배열을 반환할 수 있음.
409cheer_required, cheer_team_locked, first_bet_already_placed, bet_already_placed, point_balance_limit, idempotency_conflict, betting_closed, provider_data_stale, ledger_* 잔액·계약·context 재조회. 키 충돌은 다른 입력에 기존 키를 재사용한 문제. 무결성 오류는 임의 재지급·자동 보정 금지.
413 / 415 / 422 / 431용량·Content-Type·값/필드·헤더 오류요청 작성 수정. 같은 잘못된 입력 반복 금지. 408은 본문 수신 시간 초과.
429속도 제한Retry-After만큼 대기. 버튼 중복 제출 중지. IP 변경으로 우회하지 않음.
503database_unavailable / auth_not_configured / service_unavailable / provider 장애 등일시 장애 표시. 기존 공개 데이터 유지 가능, 개인 응답을 성공처럼 만들지 않음. Retry-After 확인.

bettingClosedReason: demo_match, season_not_active, match_closed, teams_tbd, unscheduled, betting_deadline_passed, provider_data_stale, provider_data_unconfirmed, cached_snapshot. 개인 context는 추가로 bet_already_placed, cheer_required, insufficient_points를 반환합니다.

06. Vue 연결용 TypeScript

첨부 ZIP의 maintenance/backend/docs/frontend-api.ts를 프론트 src/api로 복사해 사용할 수 있습니다. OpenAPI에서 응답 타입을 생성했고 21개 연산의 호출 함수를 제공합니다. onPublicMetadata에서 stale·ageSeconds·requestId를 받을 수 있습니다. 공개 조회만 진행 중 요청을 합치며 토큰 저장·자동 POST 재시도·반복 폴링은 하지 않습니다.

import { createLoLPickApi, LoLPickApiError, createAccountResponseGuard } from './api/frontend-api';

let currentAccountId = null; // 실제 인증 상태에서 동기적으로 갱신
const privateGuard = createAccountResponseGuard();
const api = createLoLPickApi({
  apiRoot: import.meta.env.VITE_LOLPICK_API_ROOT, // 예: https://내-서버/api/v1
  getAuthScope: () => currentAccountId,
  tokenTimeoutMs: 5000,
  getAccessToken: async () => {
    const { data } = await supabase.auth.getSession();
    return data.session?.access_token ?? null; // 전달만; 서버가 신원 재검증
  }
});
const events = await api.events(2026);
const page = await api.matches({event_id: selectedSeasonId, date: selectedKoreanDate});

// 새 OAuth 로그인 콜백에서 한 번. TOKEN_REFRESHED와 구별.
await api.registerSession(crypto.randomUUID());
// 계정 변경/로그아웃 시작 시, 인증 상태 변경보다 먼저 실행:
// privateGuard.changeAccount(); api.invalidateAuth(); clearPrivateState();
// currentAccountId를 새 계정 ID로 갱신. TOKEN_REFRESHED만으로는 초기화하지 않음.
await privateGuard.run(
  () => api.matchContext(selectedMatchId),
  context => { /* 현재 계정 화면에 동기적으로 반영 */ },
  error => { /* 현재 계정 오류만 표시 */ }
);
const operationKey = crypto.randomUUID(); // 동일 제출의 재시도 동안 보존
const payload = {matchId: selectedMatchId, teamId: selectedTeamId, amount: 100};
try {
  const bet = await api.placeBet(payload, operationKey);
  // bet.currentPoints와 bet.cheer 반영 후 상세·순위·context 갱신
} catch (error) {
  if (error instanceof LoLPickApiError) {
    // error.outcomeUnknown이면 원래 입력·작업 키를 유지
    // client_auth_changed는 이전 계정 결과이므로 새 화면에 표시하지 않음
    // error.code/status/requestId/retryAfter에 따라 화면 처리
  }
  // 응답 유실이면 동일 payload + operationKey로 재확인
}

토큰 조회 제한 기본 5초, HTTP 제한 기본 15초로 각각 적용합니다. 관리자 수집은 수집+DB 예산 때문에 더 오래 걸릴 수 있어 별도 관리자 클라이언트에 충분한 timeoutMs를 설정합니다. 응답 필수 필드·타입·상태값·튜플과 안전 정수 범위는 OpenAPI에서 생성한 검사기로 확인합니다. 업무 무결성은 서버가 최종 검증합니다. 로그인 이벤트·상태 관리·디자인 컴포넌트는 실제 Vue 프로젝트에서 연결해야 합니다.

07. 공개 조회 연결 확인

자신의 백엔드 API 주소를 입력하고 한 번 조회할 수 있습니다. 페이지를 여는 것만으로 요청하지 않습니다. 인증 토큰 입력이나 쓰기 실행 기능은 없습니다. 개인·관리자 API의 수동 확인은 개발 환경 /docs와 프론트 클라이언트를 사용합니다.

페이지를 개발 프론트와 같은 origin에서 열거나 정확한 origin을 CORS_ORIGINS에 등록해야 합니다. file://의 null origin을 운영 서버에서 허용하지 않습니다. 인증/DB URL을 이 칸에 넣지 않습니다. 라이엇 등 제3자 사이트에 대한 의도적 부하·스트레스 테스트는 금지합니다.

아직 요청하지 않았습니다.

08. 연결 범위와 검증

이 자료는 백엔드 API의 계약과 가상 요청·응답 예제입니다. 실제 Vue 화면은 샘플 데이터와 브라우저 저장을 사용하는 프로토타입이며 API 연결이 필요합니다.

실행·검증 명령과 배포 구성은 backend/README.md를 참고하세요. 소스 ZIP에는 과거 검증 로그와 수정 보고서를 포함하지 않습니다. 실제 PostgreSQL·Google OAuth·AWS nginx/TLS의 실연동 검증은 별도입니다.

  1. 현재 DB revision을 확인합니다. head는 0010_concurrent_seasons이며 기존 DB에 초기화 schema.sql을 다시 실행하지 않습니다.
  2. API root, 정확한 프론트 origin, OAuth redirect와 서버의 제한 DB 역할·TLS·MFA를 구성합니다.
  3. Google 로그인→session 등록→시즌 선택→조회·응원·베팅·이력 순서로 연결합니다. 고정 6시간 만료와 계정 전환을 확인합니다.
  4. 인증 상태 변경 전 privateGuard.changeAccount()와 api.invalidateAuth()를 호출하고 개인 상태를 지웁니다. outcomeUnknown은 서버 커밋 취소를 의미하지 않으며 다른 계정으로 재전송하지 않습니다.
  5. 프론트의 샘플 일정·사용자·풀·랭킹을 실제 API와 합의된 정책으로 교체합니다. 시즌 전체 성적 랭킹 API는 아직 없습니다.
  6. PostgreSQL 잠금·트리거·권한, /ready 성공, nginx HTTPS/CORS를 실제 환경에서 확인합니다.

이 HTML은 별도 정적 연결 자료로 제공하고 운영 runtime에 포함하지 않습니다. production에서는 /docs·/openapi.json이 비활성화됩니다.
