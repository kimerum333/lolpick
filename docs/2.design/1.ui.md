# 화면 구성과 상태

상태: 디자인 제안. 레이아웃은 조정할 수 있으며, 아래 상태 구분은 기존 서비스 규칙을 화면에 표현하기 위한 것이다.

## 1. 경기 화면

상단에서는 이벤트와 경기 상태를 바꾸고, 본문에서는 경기들을 비교한다. 계정 정보는 경기 선택을 도와주는 가까운 위치에 둔다.

### 데스크톱 구상

```text
┌─────────────────────────────────────────────────────────────┐
│ lolpick     경기 · 랭킹 · 내 프로필       포인트 · 내 계정     │
├───────────────────────────────────────┬─────────────────────┤
│ 이벤트 선택 · 날짜                    │ 보유 포인트         │
│ 전체 / 베팅 가능 / 진행 중 / 종료     │ 내 응원 팀 · 인장   │
├───────────────────────────────────────┤ 이번 이벤트 내 기록 │
│ 다음 경기                             │                     │
│ 시작 시각 · 상태 · 이벤트             │                     │
│ GEN          VS          T1           │                     │
│ 예상 배당 · 베팅액 · 참여율            │                     │
│ 내 베팅 또는 [베팅하기]               │                     │
├───────────────────────────────────────┤                     │
│ 이어지는 경기 목록                    │                     │
└───────────────────────────────────────┴─────────────────────┘
```

상단 내비게이션은 비교용 제안이다. 현재 왼쪽 내비게이션과 비교해 경기 영역을 넓게 쓰는 쪽을 선택한다. 카드형과 행 목록형도 같은 정보로 비교한다. 양 팀 게이지는 팀 테마 색으로 나누고, 팀명·비율·예상 배당을 각 팀 쪽에 정렬한다.

### 모바일 정보 순서

1. 브랜드와 주요 페이지 탐색.
2. 이벤트·경기 상태 필터.
3. 보유 포인트와 응원 인장 요약.
4. 다음 경기와 나머지 경기 목록.
5. 응원 계약 상세와 도움말.

처음부터 긴 소개 문구를 읽지 않아도 경기를 찾을 수 있게 한다. 배당 두 개와 베팅 버튼은 한 경기 안에서 가까이 둔다.

### 경기와 내 베팅 상태

| 상태 | 사용자에게 보여줄 정보와 행동 |
| --- | --- |
| 베팅 가능 · 참여 전 | 시작 시각, 양 팀 예상 배당, 전체 풀, 베팅하기 |
| 베팅 가능 · 참여 후 | 내 팀, 베팅 금액, 정산 대기. 추가 베팅 동작은 정책 확정 후 설계 |
| 베팅 마감 · 경기 진행 중 | 진행 상태와 제공 가능한 스코어, 내 베팅. 신규 베팅 차단 |
| 경기 종료 · 결과 또는 정산 처리 중 | 확정된 결과와 정산 진행 상태를 구분해 표시 |
| 정산 완료 | 결과, 확정 배당, 수령액과 손익. 결과 상세 |
| 해당 조건의 경기 없음 | 현재 필터 설명과 전체 경기로 돌아가기 |

스코어·결과·정산 정보는 실제 데이터가 제공되는 범위에서 표시한다. 현재 샘플 화면의 구현 상태가 서비스 전체의 완료 상태를 뜻하지 않는다.

## 2. 베팅 화면

읽는 순서는 **경기 확인 → 팀 선택 → 금액 → 예상 결과 → 확정**이다.

- 데스크톱에서는 모달, 모바일에서는 충분한 높이의 시트 또는 전체 화면 형태를 검토한다.
- 입력을 시작할 때 팀은 미선택 상태로 두는 안을 제안한다. 사용자가 두 팀 중 하나를 직접 선택한다.
- 보유 포인트와 입력 금액을 붙여 배치한다. 금액 바로가기에는 사용할 수 없는 금액의 상태를 표시한다.
- 예상 배당과 예상 수령액에는 `예상`을 명시하고, 마감 시 최종 배당이 결정된다는 설명을 둔다.
- 확정 버튼에는 선택 팀과 금액을 담는다. 예: `T1 승리에 5,000 P 베팅`.
- 응원 팀의 상대를 선택하면 확정 버튼 앞에 인장 박탈 안내를 표시한다. 안내만 보고 계약까지 사라진다고 오해하지 않게 한다.
- 성공 후에는 선택 팀·확정한 금액·정산 대기를 보여준다. 보유 포인트와 경기 목록의 내 베팅도 함께 갱신한다.
- 잔액 부족, 잘못된 금액, 마감, 전송 실패를 구분한다. 서버 연결 후에는 처리 중 중복 확정을 막고 실패 시 입력을 유지한다.

## 3. 응원 계약과 인장

| 상태 | 표현 |
| --- | --- |
| 계약 없음 · 첫 베팅 전 | 팀 선택과 계약 안내. 진행 중 변경 금지를 확정 전에 설명 |
| 계약 없음 · 첫 베팅 후 | 이번 이벤트의 계약 체결 기회가 종료되었다는 설명 |
| 계약 있음 · 인장 보유 | 팀 이름, 이벤트, 응원 인장, 변경 불가 상태 |
| 계약 있음 · 인장 박탈 | 계약 팀은 유지해서 표시하고, 인장 박탈과 해당 이벤트 내 복구 불가를 설명 |
| 이벤트 종료 | 해당 이벤트의 최종 응원 기록과 인장 상태. 다음 이벤트 계약은 별도 |

인장은 팀을 골랐다는 표시와 해당 이벤트의 응원 상태를 함께 담는다. 인장이 없는 랭킹 사용자에게 임의의 박탈 표시를 붙이지 않는다. 계약 여부와 박탈 이유는 프로필에서 설명한다.

## 4. 랭킹

정보 순서: 연도·이벤트 → 집계 기준 → 내 순위와 손익 → 전체 랭킹.

- 표의 주 비교값은 베팅 손익이다. 적중률과 참여 경기를 함께 읽게 한다.
- 통합에서는 현재 응원 인장, 특정 이벤트에서는 해당 이벤트의 인장을 닉네임 옆에 표시한다.
- 모바일에서는 순위·닉네임·손익을 먼저 보이고 나머지 통계를 같은 사용자 행의 두 번째 줄로 배치하는 안을 검토한다.
- 아직 정산 기록이 없는 사용자의 순위와 적중률은 `—`로 표시하고 이유를 설명한다.
- 현재 프로토타입의 샘플 랭킹에는 샘플 표시를 유지한다.

## 5. 프로필

정보 순서: 닉네임·현재 응원 → 계정 전체 경제 상태 → 연도·이벤트 필터 → 선택 범위 성적과 손익 추이 → 응원 기록 → 베팅 이력.

계정 전체의 보유 포인트·부채와 선택 범위의 베팅 성적은 제목으로 구분한다. 현재 프로토타입에서는 구현된 포인트·베팅 기록·응원 기록부터 정리하고, 정산·대출·손익 차트는 데이터와 규칙이 마련될 때 확장한다.

## 6. 공통 화면 상태

- 비회원도 경기·랭킹 등 공개 정보를 탐색한다. 참여 버튼에서 필요한 인증으로 연결하는 흐름을 설계한다.
- 로딩은 경기·통계 영역 단위로 표시한다. 조회 오류에는 다시 시도할 경로를 둔다.
- 색상과 함께 텍스트·아이콘·선택 표시를 사용한다.
- 모바일 터치 영역, 키보드 탐색, 입력 오류 안내와 모달 닫기·포커스 복귀를 함께 확인한다.
